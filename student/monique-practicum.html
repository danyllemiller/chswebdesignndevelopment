02 How-To — for anything not covered in a chapter

None of this is taught directly in your coursework, so here's the actual workflow.

  1. Find what's actually broken

    Open the page and look for the broken-image icon. For a full sweep: right-click → Inspect → Network tab → reload → filter by Img. Anything red with status 404 is missing.

    Right-click the broken icon → Inspect — the src="..." is the exact path the page expects.

  2. Match the image to real chapter content

    Read the surrounding text before making or choosing a replacement. The alt="..." text on a broken <img> usually describes exactly what the original showed.

  3. Build or source the replacement

    PNG, roughly 1200–1600px wide, compressed before upload — a multi-MB PNG slows the page down for every student. TinyPNG or Adobe Express both work.

  4. Name and place the file correctly

    Every chapter has its own folder under images/, named after that chapter's page. Lowercase, hyphenated filenames — no spaces, no capitals.

  5. Hand off for deployment

    You don't have direct publish access yet, so package each fix as: chapter/page, old filename (if any), new file, and exactly where it goes. Give that to Ms. Miller — that packaged handoff is what your check-in grades on.

Why this matters: this is the real workflow a junior developer follows on a team — documenting exactly what changed, in a form someone else can act on without guessing, is being graded here as much as the image work itself.
