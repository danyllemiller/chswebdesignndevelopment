The Final Boss: Going Live

You have built the assets. You have written the code. You have learned the theory. Now, it is time to face the final boss of web development: The Public Internet.

Up until now, your websites have lived exclusively on "Localhost" (your own computer's internal server). You can see them, but no one else in the world can. What does the term 'Deployment' mean in web development? Moving files from a local private environment to a public live environment. To finish the game and prove your skills, you must deploy your projects to a real web server in the cloud.

In this chapter, we will cover the legacy methods of deployment, modern automated pipelines, the complexities of domain names, and the strict Quality Assurance (QA) testing you must execute before you hit the launch button.

The "Old School" Way: FTP Uploads

For decades, FTP was the only way to launch a website. What does FTP stand for? File Transfer Protocol. It is the standard protocol for transferring files over the internet.

How FTP Works

To use FTP, you need a specialized program. What is the name of the popular, legacy software program used as a digital 'moving truck' for FTP? FileZilla. You open FileZilla, log into your server, and manually drag your HTML/CSS files from your computer to the server's public_html folder.

The Danger: Why is the 'Old School' FTP method considered dangerous for modern team development? It is manual, error-prone, and can instantly overwrite live files with no 'undo' button.
FTP vs. SFTP: The Security Difference

Not all file transfer protocols are equal. What is the critical security difference between FTP and SFTP?

FTP — File Transfer Protocol (Insecure)
  • Transmits all data — including your server username and password — in plain, unencrypted text.
  • Any attacker who can intercept network traffic (e.g., on a public Wi-Fi) can steal your server credentials instantly.
  • Never use plain FTP on a production server. It is like mailing your house key with the address written on the envelope.
SFTP — Secure File Transfer Protocol (Safe)
  • Encrypts the entire connection — credentials, file names, and file contents are all protected in transit using SSH.
  • Industry standard for any server file transfers. FileZilla supports SFTP — simply select "SFTP" in the protocol dropdown when connecting.
  • Always use SFTP (port 22) instead of FTP (port 21) on any live production server.

The "New School" Way: Git & CI/CD

Modern developers hate dragging and dropping files manually. The industry standard is CI/CD. What does CI/CD stand for? Continuous Integration / Continuous Deployment.

What is the primary benefit of a CI/CD pipeline? It automatically updates the live website seconds after you push code to GitHub. Why is 'Continuous Deployment' safer than manual FTP? It relies on version control, meaning every update is tracked and can be instantly rolled back if a bug occurs. When using hosts like Netlify, what branch does it monitor by default for automatic deployments? The 'main' or 'master' branch.

Webhooks & CDNs

How does a modern cloud host know when you have updated your code on GitHub? Through an automated digital tripwire called a Webhook. When the webhook fires, Netlify pulls your code and distributes it across a CDN. What is the primary function of a Content Delivery Network (CDN)? To host copies of your website on servers globally so it loads fast for everyone.

Automation Warning: A CI/CD pipeline does exactly what you tell it to do. If you push a broken index.html file to GitHub, what will the CI/CD pipeline do? Automatically deploy the broken code to the live site.

Debugging the Build: Common Launch Errors

Before moving on, we must address the most common reasons student portfolios fail to load on launch day.

The Path Paradox

What is the danger of hardcoding an Absolute Path (like C:/Users/Hannah/Desktop/image.jpg) in your HTML before deployment? It works on your laptop, but will break completely when moved to a cloud server. The server does not have a "Hannah" folder! Always use relative paths.

Index & Missing Files

Which file is automatically recognized as the default homepage by almost all web servers? index.html. If you name your homepage main.html, your live site will just show an ugly directory folder list.

Furthermore, what happens if you deploy an HTML file but forget to deploy the images folder that goes with it? The images will show as broken links (404 errors) on the live site. What is a '404 Error'? Not Found (The requested page or file does not exist on the server).

Server-Side Error Troubleshooting

When your deployed site throws an error, the HTTP status code in the browser's Network tab tells you exactly where to look. Three common server errors you will encounter on launch day:

Error CodeNameCommon CauseFix
403 Forbidden File or directory permissions on the server are set incorrectly — the web server process cannot read the file. Set file permissions to 644 and folder permissions to 755 via SFTP or cPanel.
404 Not Found Wrong file path in HTML, file was not uploaded, or Linux case-sensitivity mismatch (Logo.PNG vs logo.png). Verify the exact filename and path match. Check that the file was actually deployed to the server.
500 Internal Server Error A bug in server-side code (PHP, Node.js, etc.), a misconfigured .htaccess file, or a missing dependency on the server. Check the server error log (usually in cPanel or via SSH). Debug the server-side code — the error is not in your HTML/CSS.
Pro Tip:

Case Sensitivity: Windows computers don't care about capitalization, but Linux cloud servers do! Logo.PNG and logo.png are two entirely different files on the web. Check your capitalization!

Owning Your Identity: Domains & DNS

Right now, your site lives on a free subdomain like hannah-dev.netlify.app. What is a 'Subdomain'? A prefix added to a domain name to separate content (like 'blog.mysite.com' vs 'mysite.com'). However, a custom domain projects professionalism.

How does a Custom Domain (like johndoe.com) improve a portfolio? It projects professionalism, authority, and brand ownership. When you purchase a domain name from a Registrar (like GoDaddy), how long do you typically 'own' it before having to renew? One Year.

The DNS Phonebook

What is the Domain Name System (DNS)? The internet's master phonebook that translates human-friendly names into computer-friendly IP addresses. To connect your custom domain to your host, you must edit your DNS records:

  • What is a DNS 'A Record' used for? Pointing a domain name to a specific numeric IP address.
  • What is a DNS 'CNAME Record' used for? Pointing a domain to another domain or subdomain URL (like a Netlify app link).
  • If you change a DNS setting, why might your friend in another city not see the change immediately? The change has not fully propagated across the global DNS network yet. What does 'DNS Propagation' refer to? The time it takes for a new domain setting to spread to every internet provider across the globe. How long does DNS propagation typically take? Between 24 and 72 hours in the worst case, though many providers update within minutes to a few hours. Do not panic if your domain shows a "site not found" error immediately after updating DNS records — this is expected.
Security: HTTP vs HTTPS

What is the primary difference between HTTP and HTTPS? HTTPS encrypts the data being transferred; HTTP sends it in plain text. What is the purpose of an SSL/TLS Certificate on a live website? To enable the padlock icon and encrypt data sent between the user and the server.

Pro Tip:

Vendor Lock-in: What is 'Vendor Lock-in'? When you build a site on a closed platform (like Wix) and cannot easily move your code to a different host. By buying your own domain and using GitHub, you stay independent!

Quality Assurance (QA) & Auditing

In the context of launching a site, what does QA stand for? Quality Assurance. Never send an untested site to an employer.

  • 1. The "Resize" Test (Responsiveness)

    Why should you perform the 'Resize Test' before launching? To ensure the layout doesn't break and remains fully responsive on mobile-sized screens. If your QA test reveals that your website requires horizontal scrolling on a phone, what CSS feature do you need to fix? The Media Queries and responsive widths.

  • 2. The "Link Rot" Test

    What is 'Link Rot'? When hyperlinks point to pages or resources that have been deleted or moved (resulting in 404 errors). When an external link opens in the same tab and navigates the user away from your portfolio, it breaks best practices. What attribute fixes this? target="_blank". Tools to automate link checking: W3C Link Checker (free, browser-based at validator.w3.org/checklink), Screaming Frog SEO Spider (desktop app, crawls the whole site), or browser extensions like "Check My Links." Run these before every major deployment.

  • 3. The Accessibility & Console Audits

    When conducting an 'Alt Audit' for accessibility, what are you checking? That every <img> tag has a descriptive alt="" attribute for screen readers. What should you be looking for when you open the Browser Developer Console during QA testing? Bright red JavaScript errors or failed image loads. If a user reports that a button on your live site doesn't work, what is the first debugging step you should take? Open the Browser Console to check for JavaScript errors.

  • 4. Google Lighthouse

    What is Google Lighthouse? A free, professional auditing tool built into Chrome that grades your site's performance and accessibility. What does the 'Performance' score primarily measure? How fast the page loads and becomes interactive. What does the 'SEO' score measure? Search Engine Optimization; how well search engines can understand and rank your page. If your QA test reveals that your text is light gray on a white background, which Lighthouse score will drop? Accessibility (due to low color contrast). The four Lighthouse categories are: Performance (load speed, Core Web Vitals), Accessibility (color contrast, alt text, ARIA labels), Best Practices (HTTPS active, no deprecated APIs, secure headers), and SEO (meta tags, mobile-friendly, crawlable links). A score of 90+ in all four categories is the professional standard for a client deliverable.

5. Cross-Browser Testing Checklist

Your site may work perfectly in Chrome but break in Safari or Firefox due to CSS compatibility differences. Test in at least these four browsers before launch:

  • Chrome — your primary dev browser; always test here first.
  • Firefox — handles CSS flexbox/grid slightly differently; test form layouts.
  • Safari — most critical: Safari on iOS/macOS has its own rendering engine (WebKit) and notoriously lags behind on new CSS features. Test on a real iPhone or Mac.
  • Edge — used by a significant portion of corporate/Windows users; important for B2B clients.
Testing Tools
  • BrowserStack (browserstack.com) — real device/browser testing in the cloud. Industry standard tool. Has a free tier.
  • Chrome DevTools Device Emulation — toggle the device toolbar (F12 → phone icon) to simulate different screen sizes and mobile browsers.
  • Can I Use (caniuse.com) — look up any CSS property or JS API to see which browsers support it before using it.

Pre-Launch Security Checklist

Before clicking the deploy button, run through this checklist. A professional agency never ships a site without completing every item.

Pre-Launch Security & Quality Checklist
  • No sensitive console.log() statements — remove any logs that print user data, tokens, or server responses. Open the browser console and confirm it is clean.
  • No API keys in client-side code — search your JS files for any hardcoded secrets. Keys must be in server-side environment variables only.
  • All images have descriptive alt text — required for accessibility (WCAG) and Lighthouse Accessibility score.
  • All forms have validation — both client-side (HTML5 required attribute + JS) and server-side. Test with empty inputs, invalid emails, and extreme values.
  • HTTPS is active — the padlock icon must appear in the browser address bar. Netlify enables SSL automatically; verify it is active before sharing the URL.
  • A custom 404 page exists — configure your host to display a branded "Page Not Found" page instead of a generic server error. On Netlify, create a 404.html file at the root.
  • All assets licensed for commercial use — verify that every image, font, and icon you used has a license that permits the client's commercial website. Document the licenses.
  • Google Lighthouse audit run — target 90+ in all four categories on the live URL (not localhost).
Pro Tip:

Save this checklist as a GitHub issue template in every client repository. Before every deploy, open a new issue, run through the checklist, and close it when all items are checked. This creates a documented audit trail — essential if a client ever disputes the quality of the delivered site.

Post-Launch: The Job Isn't Over When You Hit Deploy

Why it matters: Hannah's client won't disappear the moment the site goes live — a professional developer keeps auditing, updating, and reporting on a site for as long as the client relationship lasts. Skipping this step is why so many "finished" client sites go stale within a year.

What it is: A live site is a living product, not a one-time delivery. Four ongoing responsibilities every professional developer owns after launch:

1. Evaluating Content for Relevancy

Sit down with the client periodically and review the site's content together: Is the "About Us" bio still accurate? Are old promotions, events, or team members still listed? Content that was true at launch can become outdated or embarrassing within months. Relevancy review means checking with the client — not guessing on your own — whether content still reflects their business today.

2. Evaluating Content for Viability

Viability asks a different question than relevancy: is this content actually working? A blog post nobody reads, a service page that never converts a visitor into a client, or a photo gallery that just slows the page down are all technically "relevant" but not viable. Use traffic data (see Analytics below) to decide what content pulls its weight and what should be trimmed or rewritten.

3. Maintaining Site Documentation

Every professional project keeps living documentation: the original prototype/wireframes, an up-to-date site map, and a navigation structure diagram. As you add pages or restructure the nav after launch, update these documents too — six months later, neither you nor a teammate should have to reverse-engineer the live site just to understand how it's organized.

4. Analyzing Web Analytics

Tools like Google Analytics track real visitor behavior on a live site: how many people visited, which pages they viewed, how long they stayed, and where they dropped off. Analyzing this data lets you improve traffic (are visitors finding the site at all?), user experience (are they leaving from a specific broken page?), and whether the site is meeting the client's targeted goals (form submissions, purchases, contact clicks).

Trap — Where Everyone Gets Ambushed: Students assume "Deploy" is the last step in the project. In a real client relationship, deploy is the halfway point — a site with zero post-launch maintenance quietly rots: content goes stale, links break, and nobody notices traffic dropping because no one is checking the analytics.

Your Trophy Case: The Professional Portfolio

Why is a portfolio so critical for a developer seeking a job? It acts as a 'Show, Don't Tell' trophy case that proves you can actually build functioning software.

The Architecture of a Portfolio
  • 1. The Case Studies: Why is a 'Case Study' better than just a screenshot? It explains your thought process, challenges faced, and how you solved them, which employers value highly. What is the 'STAR Method' used for in a portfolio Case Study? Structuring project descriptions by explaining the Situation, Task, Action, and Result. What does the 'A' stand for? Action (What you specifically did to solve the problem). What does the 'R' stand for? Result (The final outcome of your actions).
  • 2. The Code Links: Why is it important to include a link to the GitHub Repository for your portfolio projects? So senior engineers and hiring managers can read your raw code and see how you solved problems.
  • 3. Contact Info: Why do hiring managers look for a 'Contact Information' section on a portfolio? Because if they can't easily figure out how to email you, they will move on to the next candidate.
  • 4. The Resume: Why is it recommended to include a downloadable PDF resume on your portfolio? So recruiters can print it or upload it directly into their Applicant Tracking Systems (ATS).
Boosting Your Resume: Industry Credentials & Certifications

Why it matters: A hiring manager scanning 100 resumes for a summer internship can't verify your skills firsthand — a recognized credential is a fast, trusted signal that someone else has already tested and confirmed what you claim to know.

What it is: Industry-standard credentials available in the Web Design & Development career cluster include: Google Career Certificates (UX Design, IT Support), CompTIA IT Fundamentals (ITF+), Adobe Certified Professional exams, freeCodeCamp certifications (Responsive Web Design, JavaScript Algorithms), and Nevada's own SkillsUSA competitive certifications.

How: List credentials in a dedicated "Certifications" section on your resume and portfolio, alongside the date earned. Even a certification in progress ("In Progress: freeCodeCamp Responsive Web Design") signals initiative to an employer.

Landing the Job: Applications, Interviews & Presentations

Why it matters: A flawless portfolio still needs a human to walk an employer through it — the application, interview, and pitch are the skills that actually get you hired.

What it is: Three job-readiness skills every candidate needs: a job application (a tailored resume and cover letter matched to the specific posting, not a generic copy-paste), interview skills (confidently answering behavioral questions), and presentation skills (walking a stranger through your work clearly and confidently).

How: Reuse the same STAR Method (Situation, Task, Action, Result) you used to write your portfolio Case Studies to answer spoken interview questions like "Tell me about a time you solved a difficult bug." If you already wrote the Case Study, you already have the STAR answer memorized.

Trap — Where Everyone Gets Ambushed: Students prepare a portfolio but never rehearse actually talking through it out loud. In a real interview, silently having good projects isn't enough — if you freeze up or ramble when asked "walk me through this project," the interviewer never finds out how good your work really is.
Quick Check

An interviewer asks Hannah, "Tell me about a bug you fixed." Which portfolio-writing method should she reuse to structure her spoken answer, and why does having case studies already written make this easier?

Show Answer

The STAR Method — since her portfolio Case Studies are already written in Situation/Task/Action/Result format, she can speak the same structure out loud instead of improvising an answer from scratch.

The Mindset: Defeating Imposter Syndrome

It is entirely normal to feel like you don't know enough to apply for a job. What is 'Imposter Syndrome'? A psychological feeling that you aren't a 'real' professional or aren't good enough, despite your accomplishments. What is the best way to handle 'Imposter Syndrome'? Accept that all developers feel it, keep learning, and proudly share the work you have completed.

Why should you never wait for a project to be 'perfect' before putting it in your portfolio? Software is never truly finished; it is meant to be iterated upon. Launch it, learn from it, and improve it.
