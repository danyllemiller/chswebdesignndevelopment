The System & Support Deck

Built in Google Slides, with a partner. 100 points.

Standards Addressed

Nevada Academic Content Standards for Computer Science & Integrated Technology: 9-12.CS.D.1 (abstractions hide implementation details), 9-12.CS.HS.1 (levels of abstraction between hardware/software/application), 9-12.AP.PD.4 (design working in team roles with collaborative tools) — the same standards Chapter 3's labs (The Abstraction Teardown, The Layer Interaction Map, The Troubleshooting Guide) and Chapter 4 (The Audience Rebuild, The Distributed Build) build toward.

Objective

Work with a partner to explain how a real device actually works, layer by layer, and build a troubleshooting guide someone who isn't in this class could actually follow.

Deliverable: A Google Slides deck built with a partner, minimum 6 slides. Turn in a PDF export or a text file with your share link below.

New to Google Slides or Sheets? Start here: Ch 4.0, The Office Suite, From Zero »

Steps

Each step below links to the chapter section that actually teaches how to do it — do that first if you haven't already.

  1. Pick a real everyday device you both use (phone, smart TV, car infotainment system, gaming console, etc.). It must be a different device than the one you used for your Chapter 3 activities — this project is where you prove you can run the same process on something new, not where you write up work you already finished.
  2. Abstraction Layer Map — diagram the hardware → operating system → application layers for one real function of that device (e.g. "sending a text"). How to: Ch 3.1, Abstraction & the Six Layers »
  3. Hardware/Software Interaction — explain, in your own words, what actually happens at each layer when that function runs. How to: Ch 3.2, Hardware, System Software & Apps »
  4. Troubleshooting Guide — pick one common real problem with that device and build a step-by-step flowchart a non-expert could actually follow to fix it. How to: Ch 3.3, Systematic Troubleshooting »
  5. Data Slide — embed a chart or table (built in Sheets) ranking 3+ common failure points for that device by how often they happen. How to: Ch 4.1, Designing for Your Reader »
  6. Team Credits Slide — who did what, with real evidence you worked together (comment/edit history, or a clear role split). How to: Ch 4.2, Cloud Collaboration & Team Roles »
Worked Example: What a Finished Deck Looks Like

You may NOT use this device (a library self-checkout kiosk) for your own project. It's here so you can see how every slide connects to one device and one function — pick your own device and follow the same pattern.

The Device: A library self-checkout kiosk. The Function: checking out a book.

│ APPLICATION Self-checkout program: touchscreen menus,      │
│             "Scan your card", "Scan your book"             │
├────────────────────────────────────────────────────────────┤
│ OPERATING   Drivers for scanner, RFID pad, printer;        │
│ SYSTEM      network connection; runs the app full-screen   │
├────────────────────────────────────────────────────────────┤
│ HARDWARE    Touchscreen, barcode scanner, RFID pad,        │
│             receipt printer, CPU, RAM, network card        │
└────────────────────────────────────────────────────────────┘

Slide — Hardware/Software Interaction

  • Hardware: The scanner shines light on the barcode and a sensor reads the pattern of dark and light bars as digits. The RFID pad reads the chip inside the book's label.
  • Operating system: The scanner's driver turns those digits into input (often as if they were typed on a keyboard) and hands them to the program that's open. The OS's network software carries the request to the library's server.
  • Application: The program asks the library's catalog system whether this card can borrow this book (many kiosks use a standard protocol called SIP2). It then shows the due date, tells the RFID pad to switch off the book's security setting so the exit gate won't alarm, and prints a receipt.

Slide — Troubleshooting Guide: “The barcode won't scan”

  1. Is the red scanner light on? No → tap the screen to wake the kiosk. Still off? Ask staff, the scanner is unplugged or off. Yes → go to step 2.
  2. Is the barcode wrinkled, curved, or covered by shiny tape? Yes → flatten the book open so the barcode lies flat, then go to step 3. No → go to step 3.
  3. Hold the barcode 4–6 inches from the scanner and keep it still for 2 seconds. Did it beep? Yes → done! No → go to step 4.
  4. Try a different book. Does that one scan? Yes → the first book's label is damaged; take it to the front desk. No → the scanner itself has a problem; ask staff to restart the kiosk.
