5.1 Bits, Bytes & Binary

A computer only ever stores two things: 0 and 1. Not letters, not colors, not sound. Everything you've ever seen on a screen — this sentence included — is secretly a very long string of 0s and 1s that something else knows how to interpret.

Why only two values? Physically, a computer's memory is made of billions of microscopic electrical switches called transistors (you'll meet these properly in 5.4) — and a switch only has two real states: on or off, current flowing or not. There's no physical "maybe" in between that a machine can reliably store. Binary isn't a choice programmers made for convenience — it's the only math that actually matches what the hardware itself can do.

5.1.1 Place Value in Base 2

Decimal (base 10) uses place values of 1, 10, 100, 1000. Binary (base 2) uses place values of 1, 2, 4, 8, 16, 32, 64, 128 — each one double the last.

Worked Example: Converting 01001101

128  64  32  16   8   4   2   1

  0    1   0   0   1   1   0   1

Add up the columns with a 1: 64 + 8 + 4 + 1 = 77. That's it — that's the whole trick.

Eight of these digits — a bit each — make one byte. A byte has exactly 256 possible values (2 to the 8th power), because each of its 8 bits can be either a 0 or a 1. That's not an arbitrary number — it's why an 8-bit color channel maxes out at 255, and why some old video games had a hard score limit around 65,535. The bit width sets the ceiling.

Where Everyone Gets Ambushed: 256, Not 128 or 512
  • One byte is 8 bits, and 8 bits can make 256 different patterns (2 × 2 × 2 × 2 × 2 × 2 × 2 × 2 = 256).
  • The values run from 0 to 255. That is still 256 values, because 0 counts as one of them.
  • 128 is what 7 bits can make (27), and 512 would take 9 bits (29). A byte is neither.
Breaking It Down: Converting Decimal to Binary

The Worked Example showed binary → decimal: add up the columns that have a 1. Going the other way, decimal → binary, uses the same chart but works from the left. Think of it like paying with the biggest bills first: use the biggest place value that fits, subtract it, and keep going.

Let's convert 45. Write the place values: 128, 64, 32, 16, 8, 4, 2, 1. Does 128 fit in 45? No, write 0. Does 64 fit? No, 0. Does 32 fit? Yes, write 1, and 45 − 32 leaves 13. Does 16 fit in 13? No, 0. Does 8 fit? Yes, 1, and 13 − 8 leaves 5. Does 4 fit? Yes, 1, leaving 1. Does 2 fit in 1? No, 0. Does 1 fit? Yes, 1, leaving 0.

Read the digits in order: 00101101. Check it by adding the columns with a 1: 32 + 8 + 4 + 1 = 45. ✓ Always do that check. It catches almost every mistake.

Two tips: you always write all 8 places, so a byte looks like 00101101, not just 101101. Those leading zeros are part of the byte. And when you reach 0 left over, every remaining place is a 0.

Breaking It Down: Bits, Bytes & File Sizes

A bit is the smallest piece of data: a single 0 or 1. A byte is 8 bits, enough to store one letter like "A." Everything bigger is built from bytes, the same way pages are built from letters.

Because files contain so many bytes, we use bigger units. A kilobyte (KB) is about a thousand bytes, roughly a short text document. A megabyte (MB) is about a million bytes, roughly one song or one phone photo. A gigabyte (GB) is about a billion bytes, roughly an hour of HD video. A terabyte (TB) is about a trillion bytes, the size of a large laptop hard drive.

You'll sometimes see 1 KB described as 1,024 bytes instead of 1,000. That's because computers count in powers of 2, and 210 = 1,024. For everyday purposes, "about a thousand" is close enough. The big idea is that each unit is about 1,000 times bigger than the one before it.

5.2 Hexadecimal

Binary is exact, but it's unreadable to a human — nobody wants to type out 24 digits of 0s and 1s to describe a color. Decimal doesn't map cleanly onto bytes either. Hexadecimal (base 16) exists to solve exactly this problem: it's a compression of binary designed for human eyes.

5.2.1 Why Two Hex Digits Equal One Byte

Hex uses sixteen symbols: 0 through 9, then A through F standing in for 10 through 15. Because 16 × 16 = 256 — the exact number of values in one byte — exactly two hex digits can represent any byte perfectly. That's why you'll never see a hex color code with an odd number of characters per channel.

Worked Example: Decoding #FF5733

Split it into pairs: FF 57 33. Convert each pair to decimal: FF = 255, 57 = 87, 33 = 51. That's the color's Red, Green, and Blue values — RGB(255, 87, 51), a bright orange-red.

The Actual Equation

Each hex pair has a first digit and a second digit. The formula is always the same:

decimal = (first digit × 16) + second digit

Use the digit's value, not its symbol, for A–F (A=10, B=11, C=12, D=13, E=14, F=15). Applying it to each pair of #FF5733:

  • FF: F=15 and F=15 → (15 × 16) + 15 = 240 + 15 = 255
  • 57: 5=5 and 7=7 → (5 × 16) + 7 = 80 + 7 = 87
  • 33: 3=3 and 3=3 → (3 × 16) + 3 = 48 + 3 = 51

The trap: students often think hexadecimal is a completely separate system from binary, unrelated to what they just learned. It isn't — it's literally the same data, just grouped four bits at a time and relabeled with a friendlier symbol. Nothing about the underlying value changes.

Breaking It Down: Hex & Binary: Four Bits at a Time

Here's the shortcut that makes hex so useful: every hex digit equals exactly 4 bits. Four bits can hold 16 different values (0000 through 1111), and hex has exactly 16 symbols (0–F). So you can convert between hex and binary one digit at a time, with no big math.

To convert 3C to binary, convert each digit separately into 4 bits. 3 = 0011 and C (12) = 1100. Put them side by side: 00111100. To go backward, split a byte into two groups of 4 and convert each: 0101 1010 becomes 5 and A (10), so it's 5A.

To convert a decimal number into hex, divide by 16. Take 90: 90 ÷ 16 = 5 with 10 left over. The 5 is the first digit, and the leftover 10 is the second digit, written as A. So 90 = 5A. Check it with the equation above: (5 × 16) + 10 = 90. ✓

If you remember just one table, make it this one: 8 = 1000, 9 = 1001, A = 1010, B = 1011, C = 1100, D = 1101, E = 1110, F = 1111. With those, you can convert any hex digit in your head.

5.2.2 Not Every Hex Code Is a Color

Every example so far has been a color, because colors are an easy way to see hex pairs at work — but hex is really just a general way to write any byte's value, for anything a computer stores. A single status flag, a memory address, an error code — any one byte can be written as exactly two hex digits, with no Red/Green/Blue channels involved at all.

Worked Example: A Single Byte, Not a Color

A game engine logs a player's status as the single byte 4E. That's it — one byte, two hex digits, no color involved. Convert it the exact same way as before: E = 14, so (4 × 16) + 14 = 64 + 14 = 78. Decimal 78 happens to be the ASCII code for the letter N — maybe this engine uses N to mean "New Player." One byte, one meaning, nothing about color.

Don't Confuse This With CSS Color Shorthand

If you've done any web design, you may know a 3-character hex color like #FCD is shorthand for #FFCCDD — each digit doubles to fill out a full 6-digit color. That rule exists only for CSS colors, because a color code is always 3 channels (Red, Green, Blue) glued together, and the shorthand doubles each one. A standalone byte like 4E above has nothing to do with that rule — it's one single byte, always exactly two digits, whether or not it happens to be part of a color. Don't try to "expand" a plain byte code the way you would a color code; a status flag, an error code, and a color are all just different uses of the same base-16 system, not the same rule applied three ways.

5.3 Character Encoding

A computer stores the letter A the exact same way it stores anything else: as a number. Character encoding is the agreed-upon map between numbers and the characters they represent.

5.3.1 From ASCII to Unicode

ASCII was the original standard: a 7-bit map assigning a number to every letter, digit, and basic symbol used in English. It worked — until the rest of the world needed computers too. ASCII had no room for accented letters, non-Latin alphabets like Arabic or Japanese, or emoji.

Unicode replaced it as the modern standard, with room for every writing system on Earth and far beyond ASCII's original 128 characters. Every emoji you've ever sent is a Unicode character with its own assigned number, exactly like the letter A has one.

"A" and "a" are two completely different numbers to a computer — capitalization isn't a font style, it's a different value. 😀's number is over 128,000, which is exactly why ASCII's 128-value limit could never have fit it.

Breaking It Down: Decoding a Character, Step by Step

Character encoding is really just a lookup table that everyone agrees on. When your computer sees the number 72 in a text file, it looks up 72 in the table, finds "H," and draws an H on the screen. The number is what's stored. The letter is what you see.

To decode a code yourself, first get it into decimal. If it's in binary, add the place values. If it's in hex, use the hex equation. Then look that decimal number up in an ASCII table. For example, binary 01001000 = 64 + 8 = 72, and 72 in the ASCII table is H. A few handy landmarks: capital letters start at 65 (A), lowercase letters start at 97 (a), and the digit "0" is 48.

Modern files usually store Unicode using a system called UTF-8. In UTF-8, plain English letters still take just 1 byte, exactly matching ASCII, while other characters take 2, 3, or 4 bytes. That's why a text message full of emoji is "bigger" than one with plain letters: each emoji needs several bytes.

5.4 From Bits to a Running Program

5.1-5.3 covered how data gets represented as bits. This section covers the physical hardware that actually reads those bits and makes decisions with them.

5.4.1 Transistors & Logic Gates

A transistor is a microscopic electrical switch — the physical component that makes computer logic possible at all. A modern CPU contains billions of them. Wired together in specific patterns, transistors form logic gates, tiny circuits that make true/false decisions based on binary inputs:

AND

TRUE only if BOTH inputs are TRUE.

OR

TRUE if AT LEAST ONE input is TRUE.

NOT

Flips a single input — 1 becomes 0, 0 becomes 1.

NAND / NOR

The opposite of AND / OR.

Quick Check

Breaking It Down: Logic Gates in Everyday Terms

Logic gates sound technical, but you use the same logic every day. An AND gate is like a rule that needs both things to be true. "You can go to the game if you finish your homework AND clean your room." If either one isn't done, the answer is no.

An OR gate needs at least one thing to be true. "You can get in free if you're a student OR a teacher." Either one works, and being both works too. A NOT gate simply flips the answer. If "it's raining" is true, then "NOT raining" is false.

Inside a computer, gates take 1s and 0s instead of yes and no, where 1 means true and 0 means false. By connecting millions of gates in clever patterns, computers can add numbers, compare values, and make decisions. Every calculation your phone does, from a calculator app to a video game, is built out of these simple yes/no rules running billions of times a second.

5.4.2 RAM & Clock Speed

While data is actively being worked on, it's held in RAM (Random Access Memory) — short-term memory built for lightning-fast access, wiped clean the moment the power turns off (unlike a hard drive, which keeps data with the power off). How fast the CPU can perform those logical operations is measured by its clock speed, given in Gigahertz (GHz) — a 3.0 GHz processor completes roughly 3 billion operation "ticks" every single second.

Breaking It Down: RAM: The Computer's Desk

Think of a computer like a student doing homework. The storage drive (hard drive or SSD) is the backpack, which holds everything you own, even when you're not using it. RAM is the desk, the space where you spread out what you're working on right now. The desk is much faster to reach than digging through the backpack, but it's smaller.

When you open an app, the computer copies it from storage into RAM so the processor can work with it quickly. The more apps and browser tabs you have open, the more desk space you're using. When RAM fills up, the computer has to keep shuffling things back to the slower storage, and everything starts to lag.

RAM is volatile, meaning it forgets everything when the power goes off. That's why you lose unsaved work if your computer suddenly shuts down: it was only on the desk, not saved in the backpack. Clicking Save copies your work from RAM to storage, where it stays even with the power off. Most laptops today have 8 to 16 GB of RAM.

Breaking It Down: Clock Speed & Cores

Clock speed is how many basic steps a processor can complete each second. It's measured in gigahertz (GHz), where 1 GHz means 1 billion steps per second. A 3.0 GHz processor ticks about 3 billion times every second.

Higher clock speed generally means a faster computer, but it isn't the whole story. Modern processors have several cores, which are like several workers inside one processor, each able to handle its own tasks at the same time. A 4-core processor can work on four things at once, which helps when you're running several apps or editing video.

So when you compare devices, look at both. Clock speed tells you how fast each worker is, and the number of cores tells you how many workers there are. A slightly slower processor with more cores can beat a faster one with fewer cores on big jobs, like gaming or video editing.

5.4.3 The Fetch-Decode-Execute Cycle

Billions of times per second, the CPU repeats the same three-step loop on a binary instruction: Fetch (retrieve the next instruction from memory), Decode (figure out what that instruction actually means), and Execute (carry it out using its logic gates). This Fetch-Decode-Execute cycle is the fundamental heartbeat underneath every program you've ever run — it's what a clock speed in GHz is actually counting.

StepWhat the CPU DoesTapping "7 + 5 =" on a calculator app
FetchPull the next instruction out of RAMGrabs the instruction "add these two numbers"
DecodeFigure out what the instruction means and which data it needsRecognizes this as an ADD operation and locates 7 and 5
ExecuteCarry it out using logic gates, produce a resultRuns it through the logic gates, gets 12

One cycle, one instruction, one result — then it immediately fetches the next instruction and does it again. A 3.0 GHz processor runs roughly 3 billion of these cycles every second.

5.5 Doing This in Google Sheets

Everything above works by hand — and you should still be able to do it by hand, since that's what actually proves you understand place value. But your Unit 3 project asks you to build a working reference table that converts real values automatically, the way a real tool would. That means real formulas, not typed-in answers. Here's every conversion from this chapter, as an actual Google Sheets formula.

The Conversion Functions
ConversionFormulaExample
Decimal → Binary=DEC2BIN(number, places)=DEC2BIN(20, 8) → 00010100
Binary → Decimal=BIN2DEC(binary_text)=BIN2DEC("00010100") → 20
Decimal → Hex=DEC2HEX(number)=DEC2HEX(255) → FF
Hex → Decimal=HEX2DEC(hex_text)=HEX2DEC("FF") → 255
Character → code number=CODE(text)=CODE("A") → 65
Code number → character=CHAR(number)=CHAR(65) → A
Unicode number → any character (emoji included)=UNICHAR(number)=UNICHAR(9731) → ☃
Two Things That Will Trip You Up
  • DEC2BIN's second argument controls padding. =DEC2BIN(20) alone gives you 10100 — mathematically correct, but not the 8-digit byte format this chapter uses. Add the places argument: =DEC2BIN(20, 8) gives you 00010100, padded with leading zeros to match the Worked Example above.
  • BIN2DEC wants text, not a number. Type 00010100 straight into a cell and Sheets may read it as the number 10100 and silently drop your leading zeros before your formula ever sees it. Format that column as Plain Text first (Format → Number → Plain Text), or wrap the value in quotes inside the formula itself, like =BIN2DEC("00010100").

5.5.1 Worked Example: #FF5733 With Real Formulas

Section 5.2's Worked Example decoded #FF5733 by hand. Here's the exact same conversion as formulas, using MID() to pull out each two-character pair before converting it:

A1: FF5733

Red    =HEX2DEC(MID(A1,1,2)) → 255

Green  =HEX2DEC(MID(A1,3,2)) → 87

Blue   =HEX2DEC(MID(A1,5,2)) → 51

MID(text, start, length) pulls a chunk out of a longer string — MID(A1,1,2) means "starting at character 1, grab 2 characters." That's how you split one hex code into its Red/Green/Blue pairs without retyping anything by hand.
