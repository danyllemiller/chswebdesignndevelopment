6.1 How Data Gets Organized

A pile of names, dates, and numbers dumped into one long list is technically "stored." It's just not answerable. Structure is what turns raw data into something you can actually query.

6.1.1 Four Ways to Structure Data

Flat File

Everything in one long, unstructured list. Fast to write, painful to search.

Table (Fields & Records)

Each row is one record, each column a consistent field. This is what a spreadsheet does for you automatically.

Hierarchical

Nested parent-child relationships — like folders inside folders.

Key-Value

A simple lookup: one unique key points to one value, built for speed.

Worked Example: Restructuring a Messy List

A flat list of "Jordan, 10th grade, A-, Chemistry" repeated 500 times can't answer "who's failing Chemistry?" without reading every single line. Turn it into a table with real fields — Student, Grade Level, Class, Score — and that same question becomes one sort and one glance.

The trap: students often think adding structure is pure upside. It isn't free — restructuring costs real effort up front. What it buys you is every query afterward becoming faster and actually possible. That's the tradeoff you're always making.

Activity: The Organization Audit

  1. Turn your messy list into a proper table with real, consistent fields (columns) — like Student, Grade Level, Class, Score.
  2. Write three specific questions your original messy list could NOT answer without reading every single line.
  3. Show that your new table CAN answer all three — using a sort, a filter, or a formula, not just re-reading it by eye.

6.2 Where Data Lives

The same file stored on your laptop, on a network drive, and in the cloud survives completely different disasters. Location isn't just a convenience setting — it determines who can reach your data, how fast, and what happens when something fails.

6.2.1 Comparing Storage Locations

LocationSpeedCostDurabilityWho Holds the Keys
LocalFastestFree (already own it)Low — one device, one point of failureYou
NetworkFast on-siteModerateModerateYour organization
CloudDepends on connectionOngoing subscriptionHigh — replicated across data centersA third party
ArchivalSlow to retrieveCheapest per gigabyteVery highWhoever manages the archive

The trap: students often assume the most convenient storage option is automatically the safest. It's usually the opposite. Privacy and control tend to move inversely to convenience — cloud storage is effortless precisely because you've handed control of the keys to someone else. That's a decision, not an accident, and it's worth making on purpose.

Quick Check

Which storage option trades privacy for convenience, and why? (Answer: cloud storage — a third party holds both your data and the encryption keys, in exchange for access from anywhere.)

6.3 Bits, Encoding & Compression

Before data can be organized into a table or shipped off to the cloud, it has to exist as something a computer can hold at all. Every file — text, photo, song — eventually comes down to a very long string of 1s and 0s.

6.3.1 Analog vs. Digital

Analog data is continuous — a dimmer switch, a vinyl record's groove, a mercury thermometer can sit at literally any value in between. Digital data is discrete — it's broken into a fixed set of exact steps, ultimately represented as bits (1s and 0s). A digital photo isn't a smooth image; it's a precise grid of individually-numbered pixels.

How a Computer Stores the Letter "A"

Every character you type is stored as a number, using a standard called ASCII (or its modern superset, Unicode). The letter "A" is always the number 65. One byte (8 bits) can represent 256 distinct values (28) — enough for every letter, digit, and punctuation mark on a standard keyboard, with room to spare.

6.3.2 Compression: Lossless vs. Lossy

A raw file is often bigger than it needs to be. Compression shrinks it — but not all compression works the same way:

Lossless

Shrinks the file, then rebuilds it back to exactly the original, byte-for-byte, with nothing lost. Used for text documents, code, and spreadsheets — anywhere a single wrong character matters (e.g. a ZIP file).

Lossy

Permanently throws away some detail to shrink the file much further — detail a human usually won't notice. Used for photos and music (e.g. a JPEG or MP3), where a much smaller file is worth a tiny, often-imperceptible quality drop.

Quick Check

You compress a report with a lossless algorithm, then later decompress it. What do you get back? (Answer: the exact original file, with nothing lost.)

6.3.3 Metadata & Data Dictionaries

Metadata is data about data — not the content itself, but information describing it. A photo's metadata might secretly store the date it was taken, the camera model, and the GPS location, none of which show up when you just look at the picture.

On a larger scale, a data dictionary is a document a database team keeps that explains exactly what every column in a dataset means, its expected format, and its valid values — so anyone new to the project (or a computer program reading it later) knows a column labeled dob is a date of birth in YYYY-MM-DD format, not a guess.

6.3.4 Scalability & Deletion

A storage system is scalable if it keeps working smoothly as the amount of data grows — a startup whose user base doubles every month needs a database that can handle that growth without a full redesign each time.

And when you delete a file from a standard hard drive, the data isn't actually erased right away — the space is just marked as available to be overwritten later. That's also why "permanently" deleted files can sometimes be recovered, and why sensitive drives need to be securely wiped, not just have files dragged to the trash.
