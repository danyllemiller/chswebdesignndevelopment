3.1 Abstraction & the Six Layers

You tap a photo on your phone and it appears. Nobody teaches you the electricity, the circuits, or the code involved — and that's not an accident. It's a feature called abstraction, and it's the single idea that makes computing usable by anyone.

3.1.1 Why Hiding Complexity Is the Whole Point

Hold up a phone and a car key fob in your mind. Neither one shows you what's inside, and you don't need it to — you press a button and it works. Abstraction means hiding implementation detail so the layer above doesn't need to know how the layer below actually works. Every layer of a computing system exists so the one above it can stop worrying about it.

Worked Example: Tracing "Tap a Photo"
  1. User — you tap the screen.
  2. Application — the Photos app registers the tap and requests the image file.
  3. Operating System — checks that the app has permission to read that file.
  4. Firmware — low-level code that talks directly to the storage chip.
  5. Hardware — the actual storage and display components activate.
  6. Physical circuitry — electrons move through transistors, and a picture appears.

The trap: students often think abstraction means the details don't matter. They matter constantly — you just don't need them until something breaks. A computer scientist's edge is knowing which layer to look at when it does.

A microwave, a fitness band, a traffic light — each one hides a full computing system behind one or two buttons. That's an embedded system: a computer built into a device to do one job, with the complexity abstracted away completely.

Breaking It Down: Embedded Systems

An embedded system is a small computer built into another device to do one job. You probably don't think of a microwave, a car, or a thermostat as a computer. But each one has a tiny processor, memory, and software inside it.

Embedded systems are everywhere. A new car can have dozens of them. One runs the brakes, one runs the airbags, and one runs the radio screen. Fitness bands, smart doorbells, traffic lights, washers, and even some toothbrushes have them. There are billions of them in use around the world.

They're the perfect example of abstraction. You press "Start" on a microwave and never see the program deciding how long to run the magnetron or when to beep. All of that complexity is hidden behind a few buttons, so anyone can use it without knowing anything about computers.

Breaking It Down: Spotting Abstraction in Everyday Life

Abstraction means hiding complicated details so a person can use something in a simple way. You use abstraction dozens of times a day without noticing. When you swipe to unlock your phone, you don't think about the touchscreen measuring tiny changes in electricity, the processor checking your pattern, or the operating system loading your home screen. You just swipe, and it works.

The same thing happens when you tap an app icon, press a car's gas pedal, or flip a light switch. Each one is a simple "front" that hides a huge amount of machinery behind it. You only need to know what the button does, not how it works inside.

Here's how to recognize it on a test or in real life: someone uses a simple action without knowing what's happening underneath. That's abstraction. Its whole purpose is to make powerful, complicated technology easy enough for anyone to use, and it's the reason computers are built in layers.

3.2 Hardware, System Software & Apps

You double-click an app icon. Which layer actually starts the program — the app, the operating system, or the hardware? The honest answer is all three, in a specific order, each doing a job the others can't.

3.2.1 Three Layers, Three Jobs

Hardware

Executes. The physical chips that actually do the work — nothing more.

System Software

Manages resources and mediates access to hardware. This is your operating system — Windows, macOS, ChromeOS.

Application Software

Serves you directly. The apps you actually open and use.

The handoffs between these layers have names. A system call is an app formally asking the OS to do something on its behalf. A device driver is the piece of software that lets the OS talk to one specific piece of hardware. A file permission is the OS deciding whether you're even allowed to open a file — not the app.

Breaking It Down: The Layers in Order, Bottom to Top

Picture a computer as a stack. At the bottom is the hardware: the physical chips, circuits, and memory you could actually hold in your hand. On top of the hardware sits the system software, mainly the operating system. On top of the operating system sit the applications. At the very top is you, the user.

So from bottom to top the order is: Hardware → Operating System → Application Software → User. Each layer only talks to the layers right next to it. An app never reaches down and controls the hardware itself. It asks the operating system, and the OS is the bridge that turns the app's request into instructions the hardware can carry out.

How do you tell application software from system software? Ask, "Who is this for?" Application software does a job for you: a web browser like Chrome, a spreadsheet program like Google Sheets, a game, a photo editor, a music player. System software does a job for the computer: it starts the machine, manages memory, and controls devices. If you open it on purpose to get your own work or fun done, it's almost always an application.

Breaking It Down: What the Operating System Does

The operating system (OS) is the manager of the whole computer. Windows, macOS, ChromeOS, iOS, and Android are all operating systems. It's the first big program that starts when you turn a device on, and everything else runs on top of it.

Think of the OS like a school's front office. Apps are like teachers who need things: a room, supplies, a schedule. They don't just take what they want. They ask the office. The OS decides which app gets to use the processor next, how much memory each app gets, and which app is allowed to use the camera, the speakers, or your files.

This is why one frozen app usually doesn't crash your whole computer. The OS keeps each app in its own space, and you can close the frozen one while everything else keeps running. It's also why OS updates matter so much: the OS is in charge of security for everything above it.

Breaking It Down: System Calls & Device Drivers

Apps aren't allowed to touch the hardware directly. Say an app needs to save a file, print, or take a photo. It makes a system call, which is a formal request to the OS, like "Please save this as essay.docx." The OS checks the request and then does it.

But the OS can't know how to talk to every printer, webcam, and game controller ever made. That's the job of a device driver. A driver is a small program, usually made by the company that built the device. It turns the OS's general commands into the exact steps that one device understands. It's like an interpreter between two people who speak different languages.

That's why plugging in a new printer sometimes says "installing driver." A missing or old driver is a common cause of hardware problems. If your mouse or headphones suddenly stop working after an update, check the driver first.

Breaking It Down: File Permissions

A file permission is a rule about who can do what with a file or folder. Common permissions are read (open and look at it), write (change it), and execute (run it, if it's a program).

The operating system enforces these rules, not the app. That's why you can't open another user's files on a shared family computer, and why installing new software sometimes asks for an administrator password. The OS is checking whether your account has permission to make that change.

Permissions are a security tool. They follow the same idea as "least privilege" that you'll meet in later units: each account gets only the access it needs. If a harmful program sneaks onto a student account, permissions stop it from changing the system's most important files.

Worked Example: Saving a File

You hit "Save." The application requests the write. The operating system validates that you have permission to write there. A device driver translates that request into commands the storage hardware understands. The hardware physically stores the bits. Four layers, one click.

Breaking It Down: How Your Code Becomes Something the CPU Can Run

Programmers write code in languages people can read, like Python or JavaScript. A line like print("Hello") makes sense to you, but the processor can't read it at all. The CPU only understands machine code: long patterns of 1s and 0s, each one a tiny instruction like "add these two numbers" or "move this value into memory."

So every program has to be translated into binary machine code before the hardware can run it. A compiler translates the whole program ahead of time and produces a finished file you can run again and again. Most apps you install were compiled. An interpreter translates the code a little at a time, line by line, while the program is running. Python, and JavaScript in a web browser, usually work this way.

This is abstraction again. The programmer works in a human-friendly layer, and the compiler or interpreter hides the hard job of turning that into binary. Either way the result is the same: human-readable code becomes machine code that the CPU can execute.

3.2.2 Professional File Management

The OS gives you a filing system. It doesn't give you a filing habit — that part is on you, and every professional workflow depends on it.

The Naming Rules Professionals Actually Use
  • Lowercase, no spaces — use hyphens or underscores instead.
  • Descriptive, not generic — q3-budget-draft.xlsx, not Document1.xlsx.
  • Dated where it matters, using YYYY-MM-DD so files sort correctly by date.

The trap: students often think a file's extension (.jpg, .docx) is what determines its type. It isn't — the extension is just a label the OS uses to guess which app to open it with. A file's real format is determined by its internal structure, which is why renaming photo.jpg to photo.pdf doesn't actually turn it into a PDF.

The Eight Processes
  1. Opening a photo-editing app from the desktop by double-clicking its icon.
  2. The operating system checking whether you're allowed to open a specific file.
  3. A printer driver translating "print this page" into signals the printer hardware understands.
  4. Typing a sentence into a word processor.
  5. The operating system deciding which of several open programs gets to use the CPU next.
  6. A printer physically pressing ink onto a page.
  7. A web browser rendering a webpage's text and images on screen.
  8. The operating system allocating a block of memory to a program that just opened.

3.3 Systematic Troubleshooting

Something breaks. The instinct is to panic and click randomly, or restart and hope. Neither one teaches you anything — and "restart it" isn't even always the right first move, because it can hide the actual cause and let the fault come back later.

3.3.1 The Six-Step Protocol

A fix you can't explain is luck, not troubleshooting. Real troubleshooting follows a protocol you can teach someone else:

  1. Reproduce the problem. Can you make it happen again on purpose?
  2. Identify what changed. What was different right before it broke?
  3. Isolate the layer. Use the six layers from Section 3.1 — is this hardware, OS, or app?
  4. Test one variable at a time. Change exactly one thing and observe.
  5. Document the fix. Write down what worked, in order.
  6. Verify. Confirm the fix actually holds, not just once.
The Trap: Changing Two Things at Once

Say your app is frozen. You restart your computer and reinstall the app at the same time, and now it works. Which one fixed it? You don't know — and now you can't teach anyone else the actual fix, because you tested two variables at once instead of one.

Breaking It Down: Troubleshooting in Action

Let's walk through the six steps with a real problem: "My laptop won't connect to Wi-Fi." 1. Reproduce: turn Wi-Fi off and on, and try again. Does it fail every time? Yes. 2. What changed: it worked yesterday, and last night the laptop installed an update.

3. Isolate the layer: can other devices, like your phone, connect to the same Wi-Fi? Yes. So the network itself is fine, and the problem is somewhere in the laptop: its hardware, its OS, or its Wi-Fi driver. Since an update just happened, the OS or driver is the top suspect.

4. Test one variable: first, restart the laptop and nothing else. Still broken. Next, and only next, update the Wi-Fi driver. Now it connects. Because you changed one thing at a time, you know the driver was the real fix, not the restart.

5. Document: write it down: "After the Oct. update, Wi-Fi failed; restart didn't help; updating the Wi-Fi driver fixed it." 6. Verify: restart again tomorrow and confirm it still connects. Now you have a fix you can explain and teach, not just a lucky guess.

3.3.2 Why Isolating the Layer Matters

This is where Sections 3.1 and 3.2 pay off. "Isolate the layer" only works if you already know what the layers are. A frozen mouse cursor could be hardware (a dead USB port), system software (the OS itself hung), or application (just one program not responding) — and the fix is completely different depending on which one it is.

Quick Check

A webpage won't load, but a different website loads fine. Which layer is most likely at fault — your device's network settings, or the specific website's server? (Answer: the specific website's server — since other sites work, your own network connection isn't the problem.)

Fault A

Your laptop's Wi-Fi suddenly won't connect to any network, right after you spilled a little water near the keyboard yesterday. Your friend's laptop connects to the exact same Wi-Fi network with no problem.

Fault B

One specific app keeps closing itself about five seconds after you open it. Every other app on your device works completely normally. It started right after that one app installed an update.

Breaking It Down: Step One Is Naming the Problem, and Write Everything Down

Before you can reproduce a problem, you have to identify and clearly define it. That's why many troubleshooting guides (and tests) list it as the very first step. "My computer is broken" isn't something anyone can fix. "Chrome shows an error when I open my school email, but other websites load fine" is. A clear description tells you where to start looking and keeps you from fixing the wrong thing.

As you work, write down every step you try and what happened. It feels slow, but it saves time. You won't repeat things you already tried, and if you have to ask a teacher or tech support for help, you can show them exactly what you've already ruled out.

Your notes also help the next person. If a classmate hits the same problem next week, your written steps become a ready-made fix. Professional IT teams save these notes in help-desk "tickets" and knowledge bases for exactly this reason. That's step 5 of the protocol, Document the fix, doing its job.

3.4 Input, Process, Output

Every single thing a computer does, no matter how complex, breaks down into the same three-stage cycle underneath.

3.4.1 The Three Stages

Input

Data entering the system — a keypress, a mouse click, a microphone picking up sound.

Process

The CPU (Section 3.2) does something with that data — calculates, decodes, transforms it.

Output

The result reaches you — a monitor, a speaker, a printer.

Worked Example: Playing a Song

Input: you tap play. Process: the CPU decodes the compressed audio file into raw sound data. Output: the speaker converts that data into sound waves you actually hear. Streaming a video is the exact same three-stage cycle, just with a screen doing the output instead of (or alongside) a speaker.

Typing on a keyboard is Input. A monitor, a speaker, and a printer are all Output devices — anything that presents a result back to a person, as opposed to an Input device (keyboard, mouse, microphone) that sends data in.

Quick Check

Which stage of the Input-Process-Output cycle does a monitor represent? (Answer: Output — it presents a result back to the user.)

Applying 3.3's Troubleshooting: A Blank Monitor

A monitor showing nothing at all is an Output-stage symptom — but that doesn't automatically mean the monitor itself is broken. The single best test that isolates the layer (3.3.2): swap in a different monitor (or plug your monitor into a different computer). If the second monitor also shows nothing on the same computer, the fault is upstream of Output — the computer itself. If a different monitor works fine, the original monitor is the actual problem.

3.4.2 Under the Hood: Bits, Gates, Memory & Codes

The Unit 2 test also asks what's happening inside the hardware during that Process stage. Chapter 5 goes much deeper into all of this. Here's what you need to know now.

Breaking It Down: Transistors and Binary

A computer chip is made of billions of transistors. A transistor is a tiny electrical switch, much smaller than a grain of dust, that can be either on (electricity flowing) or off (no electricity).

Computers use those two states to store everything. On means 1 and off means 0. This two-symbol system is called binary, and each single 1 or 0 is called a bit. So when people say computers "think in 1s and 0s," they really mean billions of switches being turned on and off.

Every number, word, photo, song, and video on your device is stored as a long pattern of bits. The rest of this section shows how simple on/off switches can make decisions, hold data, and turn into letters and pictures.

Breaking It Down: Logic Gates, the Hardware That Makes Decisions

When transistors are wired together in small groups, they form logic gates. A logic gate is the piece of hardware that makes true/false decisions. It takes one or two binary inputs (1 = true, 0 = false) and produces a single output. Every decision your computer makes is built from millions of these gates.

There are three gates to know. An AND gate outputs 1 only when both inputs are 1, like a door that needs two keys turned at once. An OR gate outputs 1 when at least one input is 1, like a hallway light with switches at both ends where either one turns it on. A NOT gate (also called an inverter) has one input and flips it: 1 becomes 0 and 0 becomes 1.

Breaking It Down: RAM: Where Data Waits While It's Being Used

When the processor is actively working on something, the data it needs is held in RAM (Random Access Memory). RAM is extremely fast, so the CPU can grab what it needs almost instantly. Every app you have open and every file you're editing is sitting in RAM right now.

RAM is temporary. When the power turns off, everything in RAM disappears. That's different from storage (a hard drive or SSD), which is slower but keeps your files even when the computer is off. That's why you lose unsaved work in a power outage: it was only in RAM.

Think of storage as your locker and RAM as your desk. You keep everything in the locker, but you take out only what you're working on right now and spread it on the desk, where it's quick to reach.

Breaking It Down: Hexadecimal: A Shorter Way to Write Binary

Binary gets long fast. The color white is 11111111 11111111 11111111 in binary, and that's hard for people to read or copy without making mistakes.

Hexadecimal (base 16) fixes this. It uses the digits 0 to 9 and then the letters A to F for the values 10 to 15. Every hex digit stands for exactly 4 bits, so 1111 1111 becomes just FF, and white becomes #FFFFFF.

The computer doesn't use hex. It still stores everything in binary. Hex exists for humans: it lets programmers write long binary values in a much shorter form that's easier to read. You'll see it in web color codes, error codes, and network addresses.

Breaking It Down: ASCII and Unicode: Turning Bits Into Letters

If a computer only stores numbers, how does it show letters? It uses an agreed-upon code that gives every character a number. This is called character encoding.

ASCII was one of the first. In ASCII, capital A is 65, which the computer stores as the binary 01000001. When you type A, the computer saves 65, and when it displays the text, it looks 65 up and draws an A. ASCII covers English letters, numbers, and punctuation.

Unicode is the much bigger, modern version. It includes the characters of almost every language in the world, plus symbols and emoji. ASCII and Unicode are the systems that translate binary into the text you read on screen.

Breaking It Down: Pixels: Turning Bits Into Pictures

Your screen is a grid of millions of tiny dots called pixels. Each pixel can only be one color at a time. Zoom in far enough on any photo and you'll see the little squares.

The computer stores each pixel's color as a binary number. Usually that number mixes amounts of red, green, and blue light. So an image file is really a long list of color codes, one for every pixel, in order.

To display the image, the computer reads those codes and tells each pixel on the screen which color to light up. That's how a visual output like a photo, a video, or this page is made from nothing but 1s and 0s.

Quick Check

A porch light turns on if the motion sensor sees movement OR you flip the switch. Which logic gate matches that rule? (Answer: an OR gate — at least one true input is enough.)
