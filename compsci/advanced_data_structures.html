14.1 Arrays

Write out student1, student2, student3... and keep going, and at some point it becomes obvious this doesn't scale. An array replaces all of them with one generalized container.

14.1.1 Why Generalizing Beats Repeating

An array holds many values under one name, each reachable by a numbered position called an index. Indexes start at 0, not 1 — the first element is array[0].

Worked Example: Refactoring Six Variables

Six separate variables, six separate lines every time you want to do something with all of them. One array plus one loop replaces every one of those lines — and unlike the six variables, the array works exactly the same whether you have 6 students or 600.

The trap: students often think arrays are just "a fancier way to store stuff." The real reason they matter is generalization — one loop over an array handles any number of items, while six hardcoded variables only ever handle exactly six.

The Script to Refactor
function showStudents() {
  var student1 = "Alex";
  var student2 = "Brianna";
  var student3 = "Carlos";
  var student4 = "Destiny";
  var student5 = "Ethan";
  var student6 = "Fatima";

  Logger.log(student1);
  Logger.log(student2);
  Logger.log(student3);
  Logger.log(student4);
  Logger.log(student5);
  Logger.log(student6);
}

14.2 Linked Lists

Picture students standing in a numbered row — that's an array. Inserting someone new in the middle means everyone after them has to physically shift down one spot. Now picture each student instead holding a card naming who comes next — that's a linked list, and inserting someone new only means updating two cards.

14.2.1 Honest Tradeoffs, Not a "Better" Structure

OperationArrayLinked List
Access element by indexInstantMust walk from the start
Insert in the middleEverything after it shiftsCheap — no shifting
Delete from the middleEverything after it shiftsCheap — no shifting
Search for a value by contentMust check each elementMust check each element

That last row is deliberate — not every operation favors one structure. Searching for a value (not by index) is equally slow on both, because neither one can skip ahead without checking.

Array vs. Linked List, Visualized

[AI Prompt]: A side-by-side graphic. Left: numbered boxes in a solid row labeled "Array — direct access by index." Right: circles connected by arrows to the next one labeled "Linked List — each node points to the next."

The trap: students often look for the "better" structure between the two. There isn't one — arrays win when you need instant access by position; linked lists win when you're constantly inserting and deleting in the middle. Naming both properties correctly is the actual skill being tested here, not picking a favorite.

Quick Check

Which structure wins for deleting an item from the middle of a large list, and why? (Answer: a linked list — nothing has to shift, you just update the neighboring nodes' references.)

Scenario 1

A music app's "up next" queue, where songs get added and removed from the middle of the line constantly as the user drags songs around to reorder it.

Scenario 2

A classroom's fixed roster of exactly 30 assigned seat numbers, where the teacher mostly just needs to instantly look up who sits in seat #14.
