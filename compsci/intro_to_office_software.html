4.0 The Office Suite, From Zero

Every project in this class — and most jobs you'll ever have — needs the same three tools: something to write in, something to calculate in, and something to present with. There are two competing families of these tools. Neither is "the real one" — you need to be able to use both.

Two Families, Same Three Jobs
JobGoogle (this class)Microsoft
DocumentsGoogle DocsWord
SpreadsheetsGoogle SheetsExcel
PresentationsGoogle SlidesPowerPoint

4.0.1 The One Real Difference: Where the File Lives

Word, Excel, and PowerPoint were built around a file that lives on one computer — you open it, edit it, and explicitly click Save, or it's gone. Google Docs, Sheets, and Slides were built around a file that lives in the cloud (on Google's servers, inside your Google Drive) from the moment you create it. That one design choice explains almost every difference you'll notice:

Word / Excel / PowerPoint
  • Lives as a file (.docx, .xlsx, .pptx) on one device, or synced to OneDrive.
  • You must save it yourself — closing without saving can lose your work.
  • Sharing means sending the file itself (email attachment, USB drive) or a OneDrive link.
Docs / Sheets / Slides
  • Lives in your Google Drive from the second you create it — there is no separate "file on your computer."
  • Saves itself continuously, automatically, the whole time you're working. There is no Save button because there's nothing left to save.
  • Sharing means clicking Share and sending a link — everyone opens the exact same file, live.

The trap: a student who's only ever used Word instinctively looks for a Save button in Google Docs, doesn't find one, and assumes their work isn't saved. It already is — check the top of the screen for "All changes saved in Drive." That single sentence is doing the same job Word's Save button does, just automatically.

4.0.2 Creating, Finding, and Turning In a File

Every Google file in this class follows the exact same three steps, no matter which of the three apps you're using:

  1. Create it — go to drive.google.com, click + New, and pick Google Docs, Sheets, or Slides. (Shortcuts: typing doc.new, sheet.new, or slide.new directly into your browser's address bar creates one instantly.)
  2. Find it again — every file you create is automatically saved in your Google Drive. If you lose track of it, drive.google.com's search bar finds it by name or by content.
  3. Turn it in — for a project in this class, that means either File → Download → PDF Document (uploads a snapshot to the Dropbox) or Share → Copy Link (turn in the link itself, saved in a text file). Both are covered again, with exact steps, on every Unit Project page.
Quick Check

You've been typing in a Google Doc for ten minutes and never clicked Save. Is your work saved? (Answer: yes — Google Docs saves continuously and automatically; check "All changes saved in Drive" at the top of the screen to confirm.)

4.1 Designing for Your Reader

A document or a slide deck is a tool for moving information into someone else's head. When the formatting serves the person who wrote it instead of the person reading it, that's not a style problem — it's a design failure.

4.1.1 Structure, Not Decoration

Manually bolding a line to make it look like a heading feels the same as using a real Heading style — but the document behind it is completely different.

Manual Bold

Looks like a heading. As far as the document is concerned, it's still a regular paragraph. No table of contents can find it. No screen reader announces it as a heading.

A Real Heading Style

Creates real structure. It can generate a table of contents automatically, and it's announced correctly to anyone using a screen reader.

The trap: students often think styles and manual formatting produce the same result because they can look identical on screen. They don't produce the same document. Structure is invisible until someone needs it — navigation, accessibility, a generated table of contents — and by then it's too late to add after the fact.

Breaking It Down: Using Real Styles in Docs & Slides

In Google Docs, you set a real heading with the style menu, the dropdown on the toolbar that usually says "Normal text." Click a line, open the menu, and choose Heading 1 for main sections or Heading 2 for smaller sections inside them. You can also use Format → Paragraph styles.

Once you use real headings, Docs can build a table of contents for you: click Insert → Table of contents, and it lists every heading with clickable links. Add a new section later, refresh the table, and it updates itself. The document outline panel on the left side also uses your headings, so readers can jump straight to any section.

Real lists work the same way. Use the bulleted or numbered list buttons instead of typing dashes or "1." by hand. Real lists line up neatly, renumber themselves when you add a step, and are read correctly by screen readers. The rule of thumb is to let the tool create structure rather than faking it with spaces, bold, and font sizes.

4.1.2 Slide Design: One Idea Per Slide

The most common slide mistake isn't ugly color choices — it's cramming nine bullet points onto one slide in six-point font and reading it out loud to the room.

Worked Example: Same Content, Two Slides

Bad slide: Nine bullets of dense text, tiny font, a clip-art icon nobody asked for.

Rebuilt slide: One clear headline, one supporting image, contrast that makes the text readable from the back of the room — and all nine bullets' worth of detail moved into the speaker notes, where you can actually say them out loud instead of reading them off the screen.

The detail belongs in your speaker notes. The slide carries one idea, with enough visual hierarchy that someone glancing at it for three seconds gets the point.

Activity: The Audience Rebuild

Two rebuilds: a document, then a slide.

  1. Find a real document you've written that's badly formatted — an old essay with manually bolded "headings," inconsistent fonts, no real structure. If you can't find one, write a messy one-page document on purpose (any topic) so you have something real to fix.
  2. Rebuild it using real Heading styles (not manual bold) for every section title, then generate a table of contents automatically from those headings.
  3. Build one slide the "bad" way from the Worked Example above — nine-plus cramped bullet points, tiny font — then rebuild it as one clean slide: one headline, one supporting image, and all the extra detail moved into your speaker notes instead.
  4. Name your slide's specific audience in one sentence (not "everyone" — a real, specific person or group), and justify two design decisions you made because of who that audience is.

Turn In: Your before/after document (with real headings and a generated table of contents) and your before/after slide, with your audience sentence and two justified decisions.

4.2 Cloud Collaboration & Team Roles

Put four people in one shared document with no assigned roles and watch what happens: everyone edits the easy part, nobody touches the hard part, and two people quietly delete each other's work without noticing.

4.2.1 Real Roles on a Shared Document

Owner

Controls sharing and final structure.

Editor

Makes direct changes to the content.

Reviewer

Proposes changes without touching the original directly.

That reviewer role only works because of one feature: suggestion mode. An edit changes the document immediately. A suggestion proposes a change and waits for someone to accept or reject it. Knowing which mode you're in — and choosing the right one for the moment — is the difference between a document that stays coherent and one that turns into chaos.

Breaking It Down: Sharing Permissions in Google

When you click Share on a Google Doc, Sheet, or Slides file, you choose what each person can do. A Viewer can only look. A Commenter can look and leave comments or suggestions, but can't change the content directly. An Editor can change anything, and the file's Owner controls who has access.

Pick the lowest level that lets someone do their job. A teacher grading your work only needs Viewer or Commenter. A teammate building slides with you needs Editor. Giving everyone Editor "just because" is how a whole slide deck gets accidentally deleted the night before it's due.

Also check General access at the bottom of the Share box. "Restricted" means only the people you added can open it. "Anyone with the link" means anyone who gets the link can open it, even people you never meant to share with. For school projects you turn in by link, make sure the setting lets your teacher in, or they'll see "You need access."

Breaking It Down: Suggestion Mode & Comments

To switch modes in Google Docs, click the pencil icon near the top right and choose Suggesting. Now anything you type shows up in color, and anything you delete is crossed out, instead of changing the document directly. Each change appears in the margin with Accept (✓) and Reject (✗) buttons for the owner or editors.

Suggestions are perfect for peer review. Your partner can fix a typo, reword a sentence, or cut a paragraph, and you decide whether to keep each change. Nothing is lost, and you stay in control of your own work.

Comments are for questions and feedback that aren't direct edits, like "This slide has too much text" or "Can you add a source here?" Highlight text, click the comment button (or press Ctrl+Alt+M), and type. Use @name in a comment to notify a specific teammate. When a comment is handled, click Resolve to clear it.

4.2.2 Version History as a Safety Net

Version history records who changed what and when, and lets you restore an earlier state if something goes wrong. It's the reason "someone accidentally deleted the whole project" is recoverable instead of catastrophic.

Worked Example: Resolving a Real Conflict

Two teammates edit the same paragraph at the same time from different angles. Instead of arguing over who's right, open version history, see exactly what each person changed and when, and use suggestion mode to merge the better parts of both into one final version — with a clear record of how you got there.

The trap: students often think collaboration tools are only useful for group projects in this class. In the real world, these exact tools — roles, suggestion mode, version history — are how teams collaborate across time zones, cultures, and career fields entirely remotely. The etiquette you build now is a professional skill, not a school skill.

Quick Check

A teammate proposes deleting your paragraph, but the document doesn't change until you approve it. Are they editing or suggesting? (Answer: suggesting — an edit would have changed the document immediately.)

Activity: The Distributed Build

Time to actually use the roles from 4.2.1, not just describe them.

  1. Get into a group of three. Decide together who is Owner, who is Editor, and who is Reviewer, and create one shared document.
  2. Pick a real topic (anything you're already working on for this class works) and write it together. The Reviewer must use suggestion mode for every change — never edit the document directly.
  3. As a group, resolve at least three of the Reviewer's suggestions — accept some, reject others, but talk through the decision each time instead of accepting everything automatically.
  4. Open the document's version history and confirm it shows real contributions from all three of you.

Turn In: A link to (or screenshot of) your shared document, and a screenshot of the version history showing all three members' edits.
