System Architecture

This is a classroom management web platform for a high school Web Design & Development course. It serves students, teachers (admin role), and handles gradebooks, calendars, timesheets, notebooks, and more. Everything runs on a single VPS behind Nginx as a reverse proxy to a Node.js/Express process on port 3000. 

── Request flow ─────────────────────────────────────────
Browser → Nginx (443) → Node/Express :3000
                          ├── /api/*       → server/auth.js + server/api.js
                          └── /*           → Static files from repo root

There is no PHP runtime active — some legacy .php filenames exist in the repo but Node routes intercept them at the API layer (e.g. POST /api/save-csv.php). Any .php file served as static content will return raw source text, not executed output.

Express Server

Entry point: server/server.js. Listens on port 3000. Route priority matters — API routes are mounted before the static-file middleware so URL paths like /api/save-csv.php are handled by Node, not served as a PHP file.

// Mount order in server.js
app.use('/api', authRoutes);     // auth.js
app.use('/api', apiRoutes);      // api.js
app.use('/',   express.static(…)); // everything else
Important After any change to server/ files, you must restart PM2: pm2 restart guild-server. Changes to HTML, JS, or CSS in the repo root take effect immediately — no restart needed.
Authentication System

Session-based auth via express-session. No JWT. Sessions are in memory (lost on PM2 restart).

Roles

adminSame as teacher in current implementation.

Frontend auth guard

Every page loads js/auth-guard.js via the shared navbar include. It calls GET /api/session, populates window.dacAuthData, and fires the authComplete DOM event. Scripts that need the user object must listen for that event or check window.dacAuthData after it's set.

// Pattern used by all admin JS modules
document.addEventListener('DOMContentLoaded', () => {
    if (window.dacAuthData) { setup(); return; }
    document.addEventListener('authComplete', setup, { once: true });
});

Password reset flow

Students self-service via /passwordreset.html. Temporary password = student ID; must_change_password = 1 flag forces password change on next login. Admins can also reset from the roster page.

Database Connection

Every route handler calls getDbConnection() from server/db.js, which creates a new connection per request and the handler closes it with connection.end(). There is no connection pool. For high-concurrency workloads, migrating to mysql2's createPool() is the recommended improvement.

Heads up server/db.js is not in the git repository — it exists only on the VPS. If you re-clone to a new server, recreate the file from the template in the Infrastructure section above.

Calendar System

The calendar (calendar.html + js/calendar.js) is a custom-built vanilla JS module. It renders Day, Week, Month, and Events list views using a school schedule pulled from special-dates.csv.

Data source

special-dates.csv in the repo root is the single source of truth for school schedule data. Format: one row per date, YYYY-MM-DD,TYPE,Description. The file is served as a static asset. On startup, calendar.js fetches it and builds an internal Map<dateStr, {type, description}>.

Type codeMeaning
AA-day (block schedule)
BB-day
A_MINA-day with minimum schedule
B_MINB-day with minimum schedule
CAll-period day
SSummer school
OFFNo school (holiday, break, teacher work day)
noneNon-school date with a note (holidays that fall on weekends, etc.)

Admin calendar upload

Admin can replace special-dates.csv from the admin calendar settings page. The upload posts to POST /api/save-csv.php (Node route in server/api.js), which writes the file directly to the repo root on the server using fs.writeFile. The file is not committed to git automatically — if the server file changes, commit it manually to keep the repo in sync.

View state persistence

calendar.js is a type="module" script — all its state is module-private. It writes cal_view, cal_date, cal_year, cal_month to localStorage after every navigation so state survives page reloads.

Teacher Checklist

Defined in js/admin/calendar-checklist.js (non-module IIFE). It renders below the calendar grid and shows different task lists depending on the active calendar view.

Calendar viewChecklist cadenceHoliday behavior
DayDaily tasks (today's date as period key)Hides if today is OFF and not a teacher work day
WeekWeekly tasks (ISO week of today as period key)Hides if Mon–Fri of the displayed week are all OFF
MonthMonthly tasks + Q/S addons if Q1/Q3 end or S1 end / last day falls in displayed monthAlways shown

Race condition guard

The module uses a _loadGen counter. Each call to loadView() increments the counter and captures its value as gen. After every await, the function checks gen === _loadGen; if not, it aborts without touching the DOM. This prevents a slow monthly fetch (which has more awaits for quarterly/semester sub-sections) from overwriting a later weekly result.

Teacher work day detection

An OFF date whose description contains "teacher work", "teacher training", or "prof learning" (case-insensitive) is treated as a school day for the checklist. Teachers are working even though students are off.

Frontend Auth Guard

js/auth-guard.js is loaded by the shared navbar include (includes/navbar.html) on every page. It calls GET /api/session and sets window.dacAuthData. Teacher-only UI is gated on window.dacAuthData?.isTeacher.

Pages that need auth gate their logic behind the authComplete event. If window.dacAuthData is already set when DOMContentLoaded fires (fast path), they call setup() directly.

Deployment Workflow

There is no CI/CD pipeline. Deploys are manual git pulls on the VPS.

# 1. On dev machine — commit and push
git add <files>
git commit -m "message"
git push origin main

# 2. On VPS — pull
ssh webServer
cd /srv/chswebdesignndevelopment
git pull origin main

# 3. If you changed anything in server/ — restart PM2
pm2 restart guild-server
Static files only? HTML, CSS, and JS files in the repo root take effect immediately after a git pull — no PM2 restart needed. Only changes to server/ require a restart.
PM2 Process Manager
# Check status
pm2 status

# Restart app
pm2 restart guild-server

# View logs (last 50 lines)
pm2 logs guild-server --lines 50

# Tail live
pm2 logs guild-server

# Save process list across reboots
pm2 save
pm2 startup

The app name is guild-server. If for some reason it's not in the PM2 list, start it fresh:

cd /srv/chswebdesignndevelopment
pm2 start server/server.js --name guild-server
pm2 save
Updating the School Calendar

The canonical method is through the admin calendar settings page in the browser (uploads via API). For manual edits:

# Edit directly on the server
ssh webServer
nano /srv/chswebdesignndevelopment/special-dates.csv

# Or edit locally and push — the file is in git
# Format: YYYY-MM-DD,TYPE,Description
# Example:
2027-03-29,OFF,Start Spring Break
2027-04-05,OFF,Staff Prof Learning
Date format Dates must be YYYY-MM-DD. The CSV parser filters any row that doesn't match /^\d{4}-\d{2}-\d{2}$/, so M/D/YY format rows will be silently ignored.
Known Gotchas

No PHP execution

The server is Node.js only. Any .php filenames are legacy artifacts. Node routes in server/api.js intercept them at the API layer. A raw .php file outside /api will be served as plain text.

Sessions reset on PM2 restart

express-session uses in-memory storage. Every pm2 restart signs all users out. Logged-in teachers and students will need to re-authenticate. If this is a problem, add connect-redis or session-file-store.

calendar.js is a module — module-private state

The calendar view state (currentView, selectedDate) lives inside the ES module scope and cannot be read by other scripts. Communication happens through localStorage (cal_date, cal_view, etc.) and DOM event delegation. Any new scripts that need to know what the calendar is showing must read from localStorage, not from a global variable.

selectDay() doesn't fire the radio change event

calendar.js programmatically sets radio.checked = true when a month-view day is clicked — this does not fire the change event. The checklist module handles this by also listening to click on .calendar-day cells with a small setTimeout to let the calendar update localStorage first.

db.js is not in git

If you clone to a new machine or re-provision the VPS, you must manually recreate server/db.js with the DB credentials. The template is in the Infrastructure section.

CSV cache-busting

The browser caches special-dates.csv. JS files use ?v=N query strings to bust the cache when they change. The CSV itself has no cache-busting. If you update the file and teachers report the old schedule still showing, a hard refresh (Cmd+Shift+R) clears it.
