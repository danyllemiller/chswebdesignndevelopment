3. SERVER BACKEND — HOW IT'S ORGANIZED
════════════════════════════════════════════════════════════════════════════════════════

server/server.js mounts two Express routers at /api:
  app.use('/api', require('./auth'));   // login, logout, register, password reset
  app.use('/api', require('./api'));    // all other routes (75 routes total)

server/api.js is now a clean 11-line aggregator:
  router.use('/', require('./routes/timeclock'));
  router.use('/', require('./routes/gradebook'));
  ... (9 domain route files total)

Each route file is self-contained: it imports only what it needs from db.js and
helpers.js and exports a single Express router. No route is defined in api.js itself.

helpers.js exports three functions used across multiple route modules:
  getCurrentSchoolYear()            → "2025-2026" (July 1 cutover)
  resolveCourseId(conn, sectionId)  → MariaDB lookup first, then legacy prefix fallback
  clampScore(score, max)            → bounds-check a numeric score

4. ALL API ROUTES (prefix: /api)
════════════════════════════════════════════════════════════════════════════════════════

AUTH  (server/auth.js)
  POST   /api/login
  POST   /api/logout
  POST   /api/register
  POST   /api/verify-user
  POST   /api/reset-password
  POST   /api/admin/reset-password-default

TIMECLOCK  (server/routes/timeclock.js)
  POST   /api/clockin                     legacy clock-in (kept for compatibility)
  GET    /api/timeclock/status            today's mode: 'in' | 'out' | 'done'
  GET    /api/timeclock/question          daily teacher question + punctuality options
  POST   /api/timeclock/save             write to clockins + timesheets tables
  GET    /api/admin/daily-questions       fetch teacher's wd/cs questions for a date
  POST   /api/admin/daily-questions       save/update teacher's daily questions
  POST   /api/admin/inject-timesheets     admin testing tool: write fake timesheet rows

GRADEBOOK  (server/routes/gradebook.js)
  GET    /api/student/course-gradebook    student's assignments + scores for their course
  POST   /api/submit-exam                save exam score (keeps highest score only)
  GET    /api/student/grades             all scores for a student
  POST   /api/admin/clear-all-assignments wipe all exams + responses (destructive!)
  POST   /api/admin/save-assignment       create/update an exam record
  POST   /api/admin/edit-assignment       rename exam (cascades to responses table)
  POST   /api/admin/delete-assignment     delete exam + all responses for it
  GET    /api/admin/master-gradebook-data all students, assignments, grades for admin UI
  POST   /api/admin/save-grade           inline cell grade save
  POST   /api/admin/batch-update-grades  batch grade sync (used by Google Sheets import)

ROSTER  (server/routes/roster.js)
  GET    /api/admin/roster               filtered student list (by year or active only)
  GET    /api/admin/sections             class sections (by year or active only)
  GET    /api/admin/school-years         distinct school year values across all tables
  POST   /api/admin/archive-year         archive all non-permanent sections for a year
  POST   /api/admin/archive-students     archive specific students by ID array
  POST   /api/admin/sections             create new section + course record
  PUT    /api/admin/sections/:section_id  update section's school_year or course_name
  DELETE /api/admin/sections/:section_id  delete section (blocked if students enrolled)
  POST   /api/admin/upload-roster        bulk upsert students from JSON array
  POST   /api/admin/reset-student        clear username/password for a student
  GET    /api/admin/student              single student record + payroll_roster join
  POST   /api/admin/save-student         update student fields + optional payroll_title
  DELETE /api/admin/delete-student       remove a student record
  POST   /api/admin/delete-multiple-students bulk delete by ID array

PAYROLL  (server/routes/payroll.js)

  GET    /api/payroll/timesheets         all timesheet rows for a student
  GET    /api/admin/payroll/roster        all students with pay role info (no teachers)
  GET    /api/admin/payroll/timesheets-daily  all timesheets for a specific date
  GET    /api/admin/payroll/timesheets-period timesheets for a date range

6. DATABASE TABLES
════════════════════════════════════════════════════════════════════════════════════════

Tables created at setup (originally documented in db-schema.txt):

  students             Student roster. PK: student_id (varchar 50).
                       Columns added via ALTER TABLE after initial schema:
                         course_id, school_year, archived (0/1), help_requested (0/1)
  class_sections       Maps section_id → course_id. Columns added after initial schema:
                         school_year varchar, archived tinyint(1), permanent tinyint(1)
  courses              course_id → course_name, department
  exams                Assignment/exam metadata. PK: exam_id (varchar 50).
  responses            Grade records. One row per (student_id, exam_id).
                       score stored as varchar — empty string means "not yet graded".
  questions            CS exam question bank. FK: exam_id.
  clockins             Raw clock-in/out events. type = 'in' | 'out'.
  timesheets           One row per (student_id, date).
                       clock_in / clock_out store TIME values (inserted via CURTIME()).
                       Note: db-schema.txt incorrectly shows these as datetime — the
                       live columns are TIME. The Node routes and client JS both treat
                       them as HH:MM:SS strings and combine with `date` for parsing.
  self_assessments     Chapter proficiency sliders. Unique on (student_id, chapter_id).
  notebook_entries     Student WD notebook entries. FK: student_id.
  pay_roles            Pay grade catalog. id → title, hourly_rate.
  chapters             Chapter metadata per course.
  student_responses    Per-question answer records (CS exam detail logging).
  daily_questions      Static punctuality question bank for timeclock UI.

Tables created on first request (CREATE TABLE IF NOT EXISTS in route handlers):

  teacher_daily_questions  Teacher-set daily wd/cs questions by date. Written by
                           POST /api/admin/daily-questions.
  payroll_roster           student_id → agency title + hourly_rate. Written by
                           POST /api/admin/save-student when payroll_title is provided.
  exam_progress            In-progress exam state. One row per (student_id, exam_id).
  rubrics                  Admin-defined rubric templates (JSON criteria).
  review_questions         Review game question bank (chapter, grade, q, a, options).
  teacher_checklist_state  Teacher multi-cadence checklist completion tracking.
  bell_schedule            Bell schedule periods. Populated manually by admin.
  calendar_settings        Single-row JSON blob for calendar configuration.
  shared_files             Student peer file-sharing inbox.
  chapter_projects         Project workflow specs per chapter.
  project_submissions      File submission metadata per project attempt.
  project_evaluations      Self/peer/auto scores per project.
  project_grade_aggregates Computed average of the three evaluation types, written back
                           to responses table for gradebook display.
  turnins                  CS notebook entries AND legacy turn-in events (shared table).

8. STUDENT FLOW — HOW A STUDENT USES THE SITE
════════════════════════════════════════════════════════════════════════════════════════

1. /login.html → POST /api/login → session cookie set
2. Redirect to /student/grades.html (dashboard.js)
   - GET /api/student/profile (by username from session)
   - GET /api/student/course-gradebook  → grade table
   - GET /api/student/self-assessments  → self-assessment sliders
   - POST /api/student/save-self-assessment (on slider change)
3. Timeclock widget (timeclock.js)
   - GET /api/timeclock/status → determine mode (in/out/done)
   - GET /api/timeclock/question → fetch punctuality question
   - POST /api/timeclock/save  → write clock event to clockins + timesheets
4. Payroll view (student-payroll.js)
   - GET /api/student/profile → student_id
   - GET /api/payroll/timesheets → timesheet rows
5. WD exam pages (examLogic.js)
   - POST /api/verify-user
   - GET /api/questions?exam_id=…  (PHP route — api/get-questions.php, still live)
   - POST /api/submit-exam
6. CS exam pages (preTestLogicCS.js / cs-interactive.js)
   - GET /api/cs-exam-questions?unit=1
   - GET/POST /api/student/exam-progress  (resume-on-refresh)
   - DELETE /api/student/exam-progress  (on submit)
   - POST /api/submit-exam
   - GET/POST /api/student/cs-notebook

10. HOW TO ADD A NEW API ROUTE
════════════════════════════════════════════════════════════════════════════════════════

1. Pick the correct domain file under server/routes/ (or create a new one if the
   domain doesn't fit any existing file).
2. Add the route handler. Import from '../db' and '../helpers' as needed.
3. If you created a new routes file, add one line to server/api.js:
     router.use('/', require('./routes/mynewfile'));
4. Test locally: run `node server/server.js` and hit the endpoint.
5. Commit + push + ssh webServer + git pull + pm2 restart guild-server.
6. Add the route to section 4 of this document.

Never add routes directly to server/api.js — it is only an aggregator.
Never add routes to PHP files.
